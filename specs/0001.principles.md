# Principles

***Built as if every command could launch a satellite.***

<hr>

The standard prompt is:

```text
$gsh>
```

Standard commands continue to work just as they do in a Unix shell:

```text
$gsh> git status
$gsh> ps aux | grep node
$gsh> make | tee build.log
```

Intelligence, on the other hand, is invoked with `?`:

```text
$gsh> ? which process uses the most memory?
```

`?` is a native primitive in Genshell.

Other examples:

```text
$gsh> ? Why isn't localhost:3000 responding?
$gsh> ? Free up 30 GB without deleting anything important
$gsh> ? What has changed on this machine since yesterday?
$gsh> ? Move VS Code to the left and Safari to the right.
```

> The goal is for command mode and intent mode to coexist within the same $gsh operating language.

The interactive core applies soft real-time discipline to the behavior it controls while preserving the POSIX process, terminal, and job-control model on macOS and Linux. See [Real-Time Shell Core](0002.real_time.md).

The LLM layer is provider-independent and isolated from the shell core. Providers can be selected for one request, for the current session, or persistently in [`~/.gshrc`](0006.gshrc.md); the shell remains fully functional without AI. See [LLM Integration](0003.llm.md).

The interactive surface is asynchronous: accepting one instruction immediately activates the next editor while the earlier instruction retains its own bounded output cell. AI corrections steer with `?`, while `??` creates a separate queued request. See [Asynchronous REPL](0008.async_repl.md).

Every `gsh` action is recorded. When possible, local file mutations receive boot-scoped snapshots and can be undone within a configurable storage budget (5 GiB by default); otherwise the journal records why reversal is unavailable. See [Rewind](0004.rewind.md).

`gsh` treats computer use as OS automation: typed native primitives for files, processes, services, applications, windows, displays, clipboard, networking, and accessible UI, with visual interaction only as a fallback. See [OS Automation](0005.os_automation.md).

## Benefits

- **From commands to intent.** Users can express the outcome they want directly, without having to know the relevant tools, flags, pipes, or platform-specific conventions in advance. Traditional commands remain available whenever they are useful.

- **Native, persistent operational context.** Genshell already knows the current directory, environment, command history, exit codes, output, processes, jobs, and filesystem context. After an error, it can immediately understand what happened without asking the user or agent to reconstruct the context.

- **AI as a composable Unix primitive.** Intelligence does not live in a separate chat: `?` is a native shell primitive that can participate in pipelines and redirections. Logs, diffs, and processes can be analyzed exactly where they are produced.

- **One environment for operating the computer.** Shell commands, processes, filesystems, applications, windows, and graphical interfaces can be coordinated in a single request, eliminating manual transitions between the terminal, file manager, system tools, and separate automations.

- **Safer, auditable agentic actions.** The runtime can classify the effects of each operation — read-only, local write, network access, process control, privileged, destructive, or GUI — and apply approvals, capabilities, auditing, and, where possible, semantic rollback or undo.

- **Clearer, actionable results.** Tables, charts, images, progress interfaces, notifications, and interactive actions turn long textual output into understandable views while preserving compatibility with traditional `stdout` and `stderr`.

- **Freedom to choose the model.** Codex, cloud APIs, and local models can be interchangeable providers. Users can choose based on quality, cost, privacy, and availability without tying the shell to a single vendor.

- **Local-first without operational complexity.** Genshell can detect the available hardware, recommend an appropriate runtime and model, install them in isolation, and manage their lifecycle without requiring Homebrew, Python environments, npm, or manual compilation.

- **Unix continuity and cross-platform portability.** `gsh` remains a real shell that is useful with AI disabled and works inside third-party terminals. The same mental model can follow users across macOS, Linux, and Windows even when the underlying primitives differ.

- **A shared operating surface for humans and agents.** Agents can use structured runtime primitives instead of generating Bash and interpreting its textual output. This reduces glue work, ambiguity, and fragility, turning the computer into a shared operational platform.
