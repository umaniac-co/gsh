# `~/.gshrc`

`~/.gshrc` is the user-level configuration file for Genshell. It defines shell behavior, LLM providers and routing, Rewind storage, OS Automation policy, rich terminal output, privacy, diagnostics, and named profiles.

## Goals

- Keep all persistent Genshell configuration in one discoverable file.
- Allow the same setting to be changed directly, through `gsh config`, or conversationally when the user explicitly requests it.
- Validate the complete configuration before applying any part of it.
- Make the effective value, source, type, default, and reload behavior of every setting inspectable.
- Keep credentials and other secrets outside the file.
- Preserve a fully functional shell when AI, rich rendering, or OS Automation is disabled.

## Location and lifecycle

The default user file is:

```text
~/.gshrc
```

An optional system file may provide machine-wide defaults:

```text
/etc/gsh/gshrc
```

The first interactive history setup creates the user file with mode `0600` when it is absent. An explicitly disabled history leaves an absent file untouched. Other setup flows and persistent settings may also create it. Until creation, built-in defaults and capability discovery apply.

`gsh` reads configuration before the first prompt. It may also reload the file while running. Reload is transactional: Genshell parses and validates the complete candidate configuration, calculates a typed change set, then applies all dynamic settings together. If any value is invalid, the current effective configuration remains unchanged.

Each schema entry is classified as:

- `dynamic`: applied atomically to the running session;
- `next_session`: applied when a new `gsh` session starts;
- `restart_required`: applied only after the owning runtime or terminal restarts.

Reload reports pending settings without partially activating them.

## Syntax

The file is UTF-8 text with one typed assignment per line:

```text
config.version = 1

# Comments start with `#`.
shell.prompt = "gsh$ "
shell.history.enabled = true
rewind.max_storage = 5GiB
llm.default_provider = auto
shell.path.prepend = ["~/.local/bin", "~/bin"]
```

The grammar supports:

- dotted keys;
- quoted UTF-8 strings with explicit escapes;
- booleans and integers;
- enumerated literals such as `auto`, `allow`, `ask`, and `deny`;
- durations such as `50ms`, `10s`, `15m`, `2h`, and `7d`;
- byte sizes such as `64MiB` and `5GiB`;
- homogeneous lists of supported scalar values.

Bare strings, command substitution, environment expansion, and arbitrary expressions are not supported. `~` is expanded only for keys whose schema type is `path`; environment variables are imported only through explicit environment configuration.

Unknown keys, invalid enum values, duplicate assignments in the same source, include cycles, unsafe sizes, and out-of-range values are errors. Deprecations are warnings and include an automatic migration suggestion. `config.version` selects the configuration schema and is required once the file has been created.

## Declarative configuration and shell code

`~/.gshrc` is data, not a shell program. Loading it performs no command substitution, network request, external process launch, or implicit sourcing.

Aliases, environment values, and path entries have dedicated typed keys. Shell functions or imperative initialization live in separate files and run only when explicitly named:

```text
shell.startup.source = ["~/.gsh/init.gsh"]
```

Startup files execute as user-authored shell code after configuration has been validated and applied. Their commands and effects follow the normal Genshell execution, policy, and [Rewind](0004.rewind.md) rules. Included configuration fragments remain declarative and never become executable.

## Includes

Large configurations can be split into local fragments:

```text
config.include = ["~/.gshrc.d/*.gshrc"]
```

Includes must resolve to local regular files. Glob matches are loaded in bytewise lexicographic order. Included fragments form a base layer; assignments in the including file take precedence. Symlink resolution, file ownership, permissions, cycles, and maximum nesting depth are validated before loading.

Genshell does not automatically load a configuration file from the current directory. Project-local configuration may be introduced later only with an explicit trust model; entering an untrusted repository must never execute or silently activate its settings.

## Precedence

The effective value is resolved from highest to lowest precedence:

```text
request override
session override
active profile
~/.gshrc
included user fragments
/etc/gsh/gshrc
built-in defaults and automatic capability discovery
```

Request overrides apply to one invocation. Session overrides last until that `gsh` session ends. An active profile is an overlay on the persistent user configuration.

Machine policy may mark security constraints as locked. A lower or higher configuration layer may make a locked policy stricter, but cannot weaken it. Hard Genshell invariants are not settings and cannot be overridden at any layer.

## Configuration interface

The file can be managed without opening an editor:

```text
gsh$ config get llm.default_provider
gsh$ config set llm.default_provider local
gsh$ config unset llm.default_provider
gsh$ config set --session llm.routing.allow_cloud false
gsh$ config set --profile offline llm.routing.allow_cloud false
gsh$ config explain policy.network
gsh$ config sources
gsh$ config validate
gsh$ config reload
gsh$ config edit
```

`config get` returns the typed effective value. `config explain` also shows its source, default, valid values, reload class, profile overlay, and any policy that constrains it. `config sources` shows every loaded file in load order.

CLI and conversational changes use the same schema and validation path. A conversational change must be based on explicit user intent; application content, command output, downloaded files, and provider output are never configuration authority.

Persistent edits use a same-directory temporary file, durable flush where supported, and atomic rename. Comments, ordering, and unrelated keys are preserved whenever possible. Every persistent mutation is recorded by Rewind, so a configuration edit can be inspected and undone like any other supported local file change.

## Profiles

Profiles are named overlays for recurring environments:

```text
profiles.offline.llm.default_provider = local
profiles.offline.llm.routing.allow_cloud = false
profiles.offline.network.offline = true

profiles.presentation.terminal.notifications = false
profiles.presentation.terminal.rich_output = true
```

A profile can be activated for one session:

```text
gsh$ gsh --profile offline
gsh$ profile use presentation
```

`config.active_profile` may persist a default profile. Activating a profile does not rewrite its base settings. Profiles cannot change `config.version`, include other files, store credentials, or weaken locked policy.

## Supported namespaces

The initial schema is divided into stable namespaces:

| Namespace | Purpose |
| --- | --- |
| `config.*` | Schema version, includes, strictness, migration, and active profile. |
| `shell.*` | Prompt, history, environment, path, aliases, startup files, jobs, completion, and shell options. |
| `performance.*` | Deadlines, bounded queues, worker limits, and stale-work cancellation. |
| `terminal.*` | Rich output, rendering capabilities, pager behavior, notifications, and inline-output limits. |
| `llm.*` | AI enablement, providers, models, routing, context, deadlines, streaming, and local runtime management. |
| `rewind.*` | Action journal, snapshot budget, lifetime, eviction, and cleanup. |
| `automation.*` | OS adapter selection, semantic fallbacks, UI focus, observations, and Windows bridge behavior. |
| `policy.*` | Approval decisions for declared effect classes. |
| `privacy.*` | Redaction and eligibility of sensitive runtime context. |
| `network.*` | Offline mode, proxy use, trust roots, and resumable downloads. |
| `logging.*` | Local diagnostic logs, formatting, retention, and redaction. |
| `telemetry.*` | Explicit opt-in product telemetry. |
| `updates.*` | Update channel, checks, and installation policy. |
| `profiles.<name>.*` | Named overlays of profile-compatible settings. |

Provider and platform adapters may add namespaced extension keys after registering their schema. Extensions must obey the same validation, inspection, security, and reload rules as built-in settings.

## Core configuration

```text
config.version = 1
config.include = ["~/.gshrc.d/*.gshrc"]
config.strict = true
config.active_profile = ""
```

- `config.strict` rejects unknown keys instead of ignoring them. It defaults to `true` and cannot be disabled for security-sensitive namespaces.
- `config.active_profile` selects a persistent profile; an empty value selects only the base configuration.
- Schema migrations never rewrite the file without an explicit `config migrate` action.

## Shell configuration

```text
shell.prompt = "gsh$ "
shell.async_repl.enabled = true

shell.history.enabled = true
shell.history.max_entries = 1024
shell.history.deduplicate = false
shell.history.store_failed = true
shell.history.ignore_space = true

shell.env.EDITOR = "nvim"
shell.env.PAGER = "less -FRX"
shell.preview.editor = auto
shell.path.prepend = ["~/.local/bin", "~/bin"]
shell.path.append = []

shell.aliases.gs = "git status"
shell.aliases.la = "ls -la"
shell.startup.source = ["~/.gsh/init.gsh"]

shell.completion.enabled = true
shell.jobs.notifications = true
shell.options.pipefail = true
```

`shell.env.<name>` exports an exact string. Setting a value to `unset` explicitly removes it from the Genshell environment. `shell.path.prepend` and `shell.path.append` normalize path entries and remove duplicates without evaluating shell text.

`shell.async_repl.enabled` is a boolean and defaults to `true`; omitting it is
equivalent to `true`. A non-boolean value rejects the complete configuration
candidate without partially changing the current session. The setting is
applied at session startup. Its effective precedence is:

```text
interactive /async session override
explicit GSH_REPL environment override
shell.async_repl.enabled
built-in true default
```

For `GSH_REPL`, the exact value `classic` forces classic mode and an explicit
non-`classic` value forces the managed asynchronous REPL. The exact standalone
interactive submission `/async` toggles only the current session and never
edits `~/.gshrc`; if work is live, the transition remains pending until the
shell is quiescent.

Aliases are parsed as shell source when invoked, not when configuration is loaded. Alias names and bodies are validated. When an AI-generated command uses an alias, the exact executable form after expansion remains visible under the generated-command invariant. Startup files run in listed order and a failure is reported without corrupting the interactive session.

`shell.preview.editor` accepts `auto` or an argument vector containing exactly
one `{file}` element. The vector is limited to 16 elements and 4096 bytes in
total. `auto` searches `nvim`, `vim`, and then `nano`; an explicit vector is
executed exactly and does not fall back when its editor is unavailable.
Automatic Vim and Neovim sessions enable absolute line numbers and disable
relative numbering; explicit vectors retain the user's editor configuration.
For
example:

```text
shell.preview.editor = ["nvim", "--", "{file}"]
```

History storage is separate from the Rewind action journal. Disabling command history does not disable mandatory action recording. The implementation retains a hard maximum of 1024 entries in a fixed ring. A command is private only when its complete accepted text starts and ends with an ASCII space and `ignore_space` is enabled.

Persistent history uses the owner-only text file `~/.gsh_history`. The shell
loads it before the first prompt and merges the current session into an atomic
replacement at clean shutdown. Extended-history records preserve multiline
commands and backslashes, while plain unprefixed lines remain readable for
manual import. A bounded sidecar lock serializes concurrent shell exits. The
removed encrypted vault is not read, migrated, or deleted implicitly.
For upgrade compatibility, the parser accepts the removed `unlock_ttl`,
`reminder_min`, and `reminder_max` keys using their former value syntax and
ignores them. Newly created files omit them, and other unknown keys remain
errors; users may remove these inert entries at any time.

## Performance configuration

The behavioral contract, latency definitions, and overload rules are defined in [Real-Time Shell Core](0002.real_time.md).

```text
performance.prompt_deadline = 16ms
performance.completion_deadline = 50ms
performance.background_workers = auto
performance.max_queued_work = 128
performance.cancel_stale_work = true
```

These values tune bounded optional work; they never permit slow providers, plugins, repository inspection, or network I/O to block typing or command dispatch. Values outside implementation-defined safe ranges are rejected. `auto` is derived from the current machine and can change across boots without rewriting the file.

## Terminal configuration

```text
terminal.rich_output = auto
terminal.color = auto
terminal.images = auto
terminal.tables = auto
terminal.progress = auto
terminal.actions = auto
terminal.actions.path_detection = safe
terminal.notifications = true
terminal.pager = auto
terminal.max_inline_output = 2MiB
```

`auto` uses negotiated terminal capabilities. Rich tables, charts, images, progress interfaces, and interactive actions fall back to ordinary `stdout` and `stderr` when unsupported. A renderer setting cannot change command exit status or hide canonical textual output from pipelines and redirections.

`terminal.actions` accepts `auto`, `on`, or `off`. `auto` enables mouse actions
only in the managed REPL on a usable terminal; `on` requests them explicitly,
and `off` disables them. `terminal.actions.path_detection` accepts `off`,
`known`, or `safe`: `off` retains only first-party structured references,
`known` also enables command-specific adapters, and `safe` additionally enables
the conservative path-shaped-token detector. These keys are optional in
`config.version = 1`.

`terminal.images` accepts `auto`, `on`, or `off`. `auto` selects only a Kitty
or iTerm2 protocol confirmed by capability reporting. `on` permits the
same bounded capability probes even when no terminal-specific environment hint
is present; it does not force an unconfirmed protocol. `off` avoids the probes
and uses dimension-preserving textual placeholders. The setting affects only
interactive preview rendering: pipes, redirects, scripts, and non-interactive
SSH never receive image escapes or private preview metadata.

## LLM configuration

The complete behavioral contract is defined in [LLM Integration](0003.llm.md). Representative persistent settings are:

```text
llm.enabled = true
llm.default_provider = auto
llm.request_timeout = 2m
llm.streaming = true

llm.providers.codex.auth = chatgpt
llm.providers.openai.model = gpt-default
llm.providers.openai.credential = "keychain:openai-api"
llm.providers.local.engine = ds4
llm.providers.local.model = local-default

llm.routing.allow_cloud = true
llm.routing.prefer_local = false
llm.routing.sensitive_data = local_only

llm.context.history_entries = 20
llm.context.command_output_limit = 1MiB
llm.context.environment_allow = ["LANG", "LC_ALL", "TERM"]

llm.local.root = "~/.genshell"
llm.local.hardware = auto
llm.local.auto_install = ask
llm.local.verify_downloads = true
llm.local.resume_downloads = true
llm.local.auto_start = true
llm.local.idle_timeout = 15m
```

Provider selection can be overridden for one request, the current session, or a named profile. Automatic routing considers provider capabilities, privacy policy, availability, latency, and the task; it never sends context to cloud services when `allow_cloud` is false or `sensitive_data` requires local execution.

Local installation detects OS, architecture, memory, GPU backends, and free space. Downloaded runtimes and models are versioned, hash- or signature-verified, installed under `llm.local.root`, and managed without requiring system-wide package managers. Automatic installation follows `allow`, `ask`, or `deny`; it never occurs silently when the value is `ask`.

## Rewind configuration

The full behavior is defined in [Rewind](0004.rewind.md).

```text
rewind.enabled = true
rewind.max_storage = 5GiB
rewind.lifetime = boot
rewind.eviction = oldest
rewind.capture = supported_local_mutations
rewind.cleanup_stale_boots = true
```

In schema version 1, `boot` is the only snapshot lifetime and `oldest` is the default eviction strategy. The budget measures physical snapshot storage. An unsupported or over-budget action still executes without an inline warning; its journal entry records that no complete snapshot exists and why reversal is unavailable.

`rewind.enabled = false` may disable snapshot creation, but not the structured action journal. Every action remains recorded with its reversibility state so humans and LLMs can distinguish reversible, partially reversible, and irreversible effects.

## OS Automation configuration

The runtime contract and platform adapters are defined in [OS Automation](0005.os_automation.md).

```text
automation.enabled = true
automation.adapter = auto
automation.semantic_fallback = allow
automation.visual_fallback = ask
automation.ui.focus_policy = serialize
automation.ui.default_timeout = 10s
automation.observation.screenshots = when_needed

automation.linux.display_backend = auto
automation.windows.mode = wsl_bridge
automation.windows.host = auto
automation.windows.host_auto_start = true
```

Fallback values are `allow`, `ask`, or `deny`. They control whether a weaker mechanism may be used when a semantic API is unavailable; the selected mechanism and its limitations remain observable. Global focus and synthesized input stay serialized even if other automation operations run concurrently.

Adapter settings cannot bypass Accessibility consent, Screen Recording consent, Wayland portals, UAC, sandbox boundaries, or any other native permission system. Disabling automation does not disable ordinary shell commands.

## Effect policy

Every executable plan declares its effects. Each class has an `allow`, `ask`, or `deny` decision:

```text
policy.read_only = allow
policy.local_write = allow
policy.process_control = ask
policy.network = ask
policy.destructive = ask
policy.privileged = ask
policy.gui_side_effect = ask
```

Policies are evaluated after an action is fully resolved but before its first covered effect. Compound actions use the strictest applicable decision. `ask` produces a concise approval containing the relevant operation, target, and effect class; it is unrelated to Rewind snapshot availability, which remains silent during normal execution.

Machine policy and platform permissions can always reduce authority. No configuration value grants authority the operating system, current user, or calling client does not already possess.

## Privacy and context

```text
privacy.environment.deny = ["*_TOKEN", "*_SECRET", "*_PASSWORD", "*_KEY"]
privacy.redaction.additional = ["COMPANY_INTERNAL_*", "PRIVATE_*"]
privacy.clipboard.model_context = deny
privacy.screenshots.model_context = ask
privacy.secure_fields.model_context = deny
privacy.rewind_contents.model_context = deny
```

Context policies use `allow`, `ask`, or `deny`. More specific deny rules override general allow rules. Secure fields, credentials, protected clipboard content, and Rewind snapshot contents are denied by default. Redaction happens before diagnostic logging or provider transmission.

The action journal may expose non-secret metadata to the LLM, including the fact that an action was not reversible and its stable reason code. It does not expose snapshot contents automatically.

## Network and downloads

```text
network.offline = false
network.proxy = env
network.ca_bundle = system
network.resume_downloads = true
network.max_concurrent_downloads = 2
```

Offline mode prevents provider, update, and model-download network access initiated by Genshell. It does not rewrite the behavior of arbitrary commands launched by the user; `policy.network` governs Genshell plans whose effects can be classified in advance.

Proxy and trust-root settings affect Genshell-owned clients only. Runtime and model downloads use resumable temporary files and are verified before activation.

## Diagnostics, telemetry, and updates

```text
logging.enabled = true
logging.level = info
logging.format = text
logging.directory = "~/.genshell/logs"
logging.retention = 7d
telemetry.enabled = false

updates.channel = stable
updates.check = automatic
updates.auto_install = false
```

Diagnostic logs and the Rewind action journal are separate stores. Disabling diagnostics does not disable action recording. Sensitive-data redaction is mandatory for diagnostic output and cannot be turned off in normal builds.

Product telemetry is opt-in and disabled by default. Enabling it must show the exact data classes collected and never includes command text, file contents, prompts, model context, credentials, screenshots, clipboard data, or Rewind snapshots.

Update checks honor offline mode and network policy. Updates are signature-verified. Automatic installation is disabled by default and never replaces a running shell binary in place.

## Secrets and file security

Secrets are never stored as plaintext values in `~/.gshrc`. The file may select an authentication method or contain an opaque credential reference:

```text
llm.providers.openai.credential = "keychain:openai-api"
```

Secret management uses the OS credential store or provider-owned secure storage:

```text
gsh$ config set --secret llm.providers.openai.credential
```

The secret value is collected through a protected input path and only a reference is persisted. It is never echoed, entered into command history, diagnostic logs, Rewind snapshots, or model context.

Genshell verifies ownership and rejects configuration sources writable by an untrusted user. It warns when the main file or include fragments have unnecessarily broad permissions. Includes cannot use remote URLs, named pipes, devices, or world-writable directories.

## Non-configurable invariants

The following behaviors are part of the Genshell contract and cannot be disabled in `~/.gshrc`:

- AI-generated shell commands are shown in full, in execution order, before execution.
- Native OS operations have an explicit readable representation.
- Every Genshell action receives an action-journal record and reversibility state.
- An unavailable snapshot is never presented as a complete rollback point.
- The LLM cannot authorize operations or bypass capability and effect policy.
- Native OS permissions, sandbox boundaries, and privilege controls remain authoritative.
- Provider output and external content are data, not configuration authority.
- The interactive shell core remains usable when AI, providers, automation adapters, and rich rendering are unavailable.
- Secrets are not written to configuration, history, logs, snapshots, or model context.

## Failure behavior

- Syntax, type, range, and unknown-key errors identify the exact source and line.
- A failed initial user-configuration load starts the interactive shell with built-in safe defaults and all optional integrations disabled, while preserving any valid locked system policy; the error is reported before the first prompt.
- A failed reload keeps the complete previous configuration active.
- Missing optional include globs are allowed; explicitly named missing files are errors.
- A failed dynamic reconfiguration rolls back every setting already staged for that reload.
- Provider, renderer, or adapter configuration failure degrades only that component and cannot prevent ordinary shell operation unless the user explicitly configured a fail-closed policy.
- Configuration writes interrupted before atomic rename leave the previous file intact.

## Verification

Black-box tests run the real `gsh` executable and verify:

- parsing, typed values, comments, includes, profiles, and every precedence layer;
- rejection of unknown keys, duplicates, invalid types, unsafe paths, include cycles, and incompatible schema versions;
- transactional startup, reload, rollback, and atomic persistent writes under injected failures;
- dynamic, next-session, and restart-required behavior;
- `get`, `set`, `unset`, `explain`, `sources`, `validate`, `reload`, `edit`, and migration commands;
- equivalent results for direct, CLI, and explicitly requested conversational edits;
- preservation of comments and unrelated settings during structured writes;
- credential-store references and the absence of secret values from files, history, logs, snapshots, and model context;
- enforcement of locked policy and non-configurable invariants;
- continued shell operation with invalid optional-provider, terminal, or automation configuration;
- Rewind records for persistent configuration mutations and successful undo of supported edits.
